### 💭 第一印象
プロジェクト史上最大の構造改革。モノリシックな main.py からクリーンアーキテクチャへの転換。6コミットに凝縮された大規模リファクタリング。ワクワクすると同時に、既存テスト71件が壊れないかの緊張感。

## 🧠 思考の軌跡
1. **設計フェーズ**: まず Firestore のコレクション設計（snapshots/runs/events/deliveries）と Outbox パターンの設計ドキュメントを作成。at-least-once delivery を保証する設計を練った。
2. **基盤レイヤー**: `ports.py` (Protocol定義)、`models.py` (frozen dataclass の value objects)、`config.py` (環境変数の一括パース・バリデーション) を追加。依存性注入の基盤を整備。
3. **ユースケース層**: `usecase.py` (ローカルバックエンド用) と `firestore_usecase.py` (Firestoreバックエンド用) を分離。ビジネスロジックをインフラから独立させた。
4. **インフラ層**: `firestore_store.py` で Firestore の CRUD を実装。`delivery.py` で指数バックオフ付きリトライを実装。
5. **統合**: `main.py` を `STATE_BACKEND` の値に応じて local/firestore を切り替えるルーティングに書き換え。
6. **CI**: `daily-credit-check.yml` に GCP Workload Identity Federation (WIF) 認証を追加。サービスアカウントキーを使わない安全な認証方式。

## ✨ 今日のハイライト！
最も感動的だったのは、main.py の 200行削除・363行追加のリファクタリングが完了し、既存の71テストが全てグリーンのままだった瞬間。Protocol ベースの DI のおかげで、テストのモック差し替えが容易だった。

`_build_source_plans()` で lambda クロージャの変数キャプチャ問題を回避するために if ブロック内のローカル変数に束縛するテクニックは、Python のスコープを深く理解していないと書けない。

## 🤔 ちょっと、ひとりごと…
- `firestore_store.py` と `firestore_usecase.py` で合計489行のコードにユニットテストがない。mock Firestore client を使ったテストが必要。
- `_ttl_after()` が ISO文字列を返しているが、Firestore TTL は timestamp 型のみ対応。修正が必要。
- `finish_run()` が try/finally で保護されていない。例外時に run が "running" のまま残る。
